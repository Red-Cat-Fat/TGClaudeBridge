# TGClaudeBridge — Claude Code в Telegram

Отошли от компьютера — Claude Code пишет вам в Telegram, а вы отвечаете с телефона:

- **❓ Вопрос с кнопками.** Когда Claude спрашивает (`AskUserQuestion`), вопрос приходит с вариантами-кнопками,
  мультивыбором и кнопкой «✏️ Свой ответ». Ответ уходит обратно в сессию — работа продолжается без вас за ПК.
- **✅ Claude закончил.** Приходит полный текст последнего ответа. Ответьте на это сообщение (reply) —
  текст уйдёт в сессию как ваше новое сообщение, и Claude продолжит работу. Так можно переписываться с телефона.
- **🔐 Нужно разрешение.** Уведомление, что Claude ждёт подтверждения инструмента (подтвердить можно только на ПК).

Каждое сообщение подписано: проект, git-ветка и тема сессии (ваш первый запрос). Параллельные сессии не путаются —
ответ уходит той сессии, на чьё сообщение вы ответили.

Пока вы за компьютером, ничего не отправляется. «Не за компьютером» — мышь и клавиатура не трогались заданное
время. Вернулись к ПК — за пару секунд ожидание в Telegram снимается, и вопрос показывается в окне Claude Code.

## Быстрая настройка

Нужны [Claude Code](https://claude.com/claude-code) и [Node.js](https://nodejs.org) 18+.

```bash
git clone https://github.com/Red-Cat-Fat/TGClaudeBridge.git
```

Запустите мастер настройки:
- **Windows** — двойной клик по `setup.cmd`;
- **macOS / Linux** — `sh setup.sh`.

Мастер по шагам:
1. попросит токен бота (создаётся в [@BotFather](https://t.me/BotFather) командой `/newbot`) и проверит его;
2. попросит написать боту и сам найдёт ваш chat id;
3. спросит, через сколько минут простоя считать, что вы отошли;
4. пришлёт тестовое сообщение, сохранит настройки в переменные окружения;
5. предложит сразу установить плагин в Claude Code.

После мастера перезапустите Claude Code.

> Нужен **отдельный бот**: если у бота настроен webhook или его читает другая программа, ответы не дойдут.

## Ручная установка

1. Бот в [@BotFather](https://t.me/BotFather), ваш chat id — у [@userinfobot](https://t.me/userinfobot). Напишите своему боту `/start`.
2. Переменные окружения:
   - Windows: `setx CLAUDE_TG_BOT_TOKEN "<токен>"` и `setx CLAUDE_TG_CHAT_ID "<chat id>"`
   - macOS / Linux: `export CLAUDE_TG_BOT_TOKEN=...` и `export CLAUDE_TG_CHAT_ID=...` в `~/.zshrc` или `~/.bashrc`
3. Плагин — в Claude Code:
   ```
   /plugin marketplace add Red-Cat-Fat/TGClaudeBridge
   /plugin install telegram-bridge@tg-claude-bridge
   ```
   Хуки подключаются сами, `settings.json` править не нужно.
4. Перезапустите Claude Code.

## Проверка

Попросите Claude: «Задай мне тестовый вопрос через AskUserQuestion» — и не трогайте компьютер дольше порога простоя.
Для проверки сидя за ПК есть тестовый режим `CLAUDE_TG_IDLE_MIN=0`: всё уходит в Telegram, но и возврата на ПК
нет — после проверки верните обычное значение.

Самопроверка скриптов: `node --test`.

## Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `CLAUDE_TG_BOT_TOKEN` | — | токен бота (обязательно; подходит и `TELEGRAM_BOT_TOKEN`) |
| `CLAUDE_TG_CHAT_ID` | — | ваш chat id (обязательно; подходит и `TELEGRAM_CHAT_ID`) |
| `CLAUDE_TG_IDLE_MIN` | `3` | минуты простоя до «вы отошли»; дробные — `0.5` = 30 с; `0` — тестовый режим |
| `CLAUDE_TG_STAGE_LOG` | — | путь (от корня репозитория) к JSONL-журналу стадий `{ts, event: start\|stop, topic, stage, name}` — тогда в сообщениях видна текущая стадия |

Мастер настройки можно запускать повторно — он перезапишет значения.

## Как это устроено и ограничения

- Всё работает локально: хуки Claude Code запускают Node-скрипт, он сам ходит в Telegram Bot API.
  Модель не вызывается, токены Claude на сообщения не тратятся. Токен бота никуда, кроме Telegram, не уходит
  и в лог не пишется. Принимаются сообщения только из вашего chat id.
- Ожидание ответа — до 55 минут, за 5 минут до конца бот предупредит. Потом вопрос возвращается в окно Claude Code.
- Несколько сессий: очередь бота читает одна ждущая сессия и раскладывает сообщения остальным
  (`~/.claude/telegram-bridge/`). Если ждут несколько сессий — отвечайте реплаем на нужное сообщение.
  Если бота читает ещё кто-то (вторая копия моста, бот на сервере), придёт предупреждение.
- Запросы разрешений из Telegram подтвердить нельзя — только уведомление.
- Простой ПК: Windows — встроенно; macOS — через `ioreg`; Linux — нужен `xprintidle` (X11; на Wayland не работает).
  Если простой измерить не удалось, мост считает, что вы за компьютером, и молчит. macOS и Linux не проверялись.
- macOS: приложения не видят переменные из `~/.zshrc`. Мастер дополнительно задаёт их через `launchctl setenv`,
  но только до перезагрузки — потом запустите мастер снова или открывайте Claude Code из терминала.
- Лог ошибок: `~/.claude/telegram-bridge/bridge.log`.
