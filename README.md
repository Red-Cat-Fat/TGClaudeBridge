# Telegram Bridge для Claude Code

Отошли от компьютера — Claude Code пишет вам в Telegram:

- **❓ Вопрос с кнопками.** Когда Claude спрашивает (`AskUserQuestion`), вопрос приходит с вариантами-кнопками,
  мультивыбором и кнопкой «✏️ Свой ответ». Ответ уходит обратно в сессию — работа продолжается без вас за ПК.
- **✅ Claude закончил.** Приходит полный текст последнего ответа. Ответьте на это сообщение (reply) —
  текст уйдёт в сессию как ваше новое сообщение, и Claude продолжит работу. Так можно переписываться с телефона.
- **🔐 Нужно разрешение.** Уведомление, что Claude ждёт подтверждения инструмента (ответить можно только на ПК).

Каждое сообщение подписано: проект, git-ветка и тема сессии (ваш первый запрос), так что параллельные сессии
не путаются — ответ уходит той сессии, на чьё сообщение вы ответили.

Пока вы за компьютером, ничего не отправляется. «Не за компьютером» — мышь и клавиатура не трогались
`CLAUDE_TG_IDLE_MIN` минут (по умолчанию 3). Вернулись к ПК — ожидание в Telegram снимается, вопрос показывается в окне.

## Установка

Нужны Claude Code и Node.js 18+.

1. **Бот.** В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → сохраните токен.
   Нужен **отдельный бот**: если у бота настроен webhook или его читает другая программа, ответы не дойдут.
   Напишите своему боту `/start`.
2. **Ваш chat id** — пришлёт [@userinfobot](https://t.me/userinfobot).
3. **Переменные окружения.**
   - Windows (PowerShell):
     ```powershell
     setx CLAUDE_TG_BOT_TOKEN "<токен>"
     setx CLAUDE_TG_CHAT_ID "<chat id>"
     ```
   - macOS / Linux — в `~/.zshrc` или `~/.bashrc`:
     ```bash
     export CLAUDE_TG_BOT_TOKEN="<токен>"
     export CLAUDE_TG_CHAT_ID="<chat id>"
     ```
   Перезапустите Claude Code (и терминал/приложение), чтобы он увидел переменные.
4. **Плагин.** В Claude Code:
   ```
   /plugin marketplace add <путь к этой папке или git-URL репозитория>
   /plugin install telegram-bridge@claude-telegram-bridge
   ```
   Хуки подключаются сами, `settings.json` править не нужно.

## Проверка

Временно включите тестовый режим — всё уходит в Telegram, даже если вы за ПК:
`CLAUDE_TG_IDLE_MIN=0` (Windows: `setx CLAUDE_TG_IDLE_MIN 0`), перезапустите Claude Code и попросите:
«Задай мне тестовый вопрос через AskUserQuestion». Вопрос придёт в Telegram с кнопками.
После проверки верните порог: `setx CLAUDE_TG_IDLE_MIN 3`.

Самопроверка скрипта: `node --test telegram-bridge/scripts/telegram-bridge.test.js`.

## Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `CLAUDE_TG_BOT_TOKEN` | — | токен бота (обязательно; подходит и `TELEGRAM_BOT_TOKEN`) |
| `CLAUDE_TG_CHAT_ID` | — | ваш chat id (обязательно; подходит и `TELEGRAM_CHAT_ID`) |
| `CLAUDE_TG_IDLE_MIN` | `3` | минуты простоя до «вы отошли»; дробные — `0.5` = 30 с; `0` — тестовый режим |
| `CLAUDE_TG_STAGE_LOG` | — | путь (от корня репозитория) к JSONL-журналу стадий `{ts, event: start\|stop, topic, stage, name}` — тогда в сообщениях видна текущая стадия |

## Как это устроено и ограничения

- Всё работает локально: хуки Claude Code запускают Node-скрипт, он сам ходит в Telegram Bot API.
  Модель не вызывается, токены Claude на сообщения не тратятся. Токен бота никуда, кроме Telegram, не уходит
  и в лог не пишется. Принимаются сообщения только из вашего chat id.
- Ожидание ответа — до 55 минут, за 5 минут до конца бот предупредит. Потом вопрос возвращается в окно Claude Code.
- Несколько сессий: очередь бота читает одна ждущая сессия и раскладывает сообщения остальным
  (`~/.claude/telegram-bridge/`). Если ждут несколько сессий — отвечайте реплаем на нужное сообщение.
- Запросы разрешений из Telegram подтвердить нельзя — только уведомление.
- Простой ПК: Windows — встроенно; macOS — через `ioreg`; Linux — нужен `xprintidle` (X11; на Wayland не работает).
  Если простой измерить не удалось, мост считает, что вы за компьютером, и молчит.
  macOS и Linux не проверялись.
- Лог ошибок: `~/.claude/telegram-bridge/bridge.log`.
